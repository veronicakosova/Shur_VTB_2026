# Разработка модели оценки вероятности кредитного дефолта

Проект посвящён построению модели бинарной классификации для оценки вероятности дефолта клиента по кредиту.

Основная метрика качества — ROC-AUC. В процессе работы сравниваются несколько алгоритмов машинного обучения, проводится подбор гиперпараметров и проверка устойчивости финальной модели.

## Задача

Необходимо построить модель, которая по характеристикам клиента оценивает вероятность кредитного дефолта.

Целевая переменная:

- `target = 1` — дефолт;
- `target = 0` — отсутствие дефолта.

Основная метрика:

**ROC-AUC** — показывает, насколько хорошо модель разделяет дефолтных и недефолтных клиентов.

Значение 0.5 соответствует случайной классификации, значение 1.0 — идеальному разделению.

## Структура ноутбука

### 1. Импорты и загрузка данных

Загрузка исходных данных и подключение необходимых библиотек.

### 2. Анализ данных (EDA)

Проводится первичный анализ:

- типы данных;
- пропуски;
- распределения признаков;
- выбросы;
- корреляции;
- различия между дефолтными и недефолтными клиентами.

### 3. Препроцессинг

Выполняется обработка пропущенных значений.

В зависимости от смысла признака используются:

- заполнение нулями — если пропуск означает отсутствие продукта или операции;
- заполнение медианой — если значение признака неизвестно.

Для части моделей используется стандартизация признаков.

### 4. Отбор признаков

Используется RFECV (Recursive Feature Elimination with Cross-Validation) для определения информативного набора признаков.

### 5. Логистическая регрессия

Логистическая регрессия используется как базовая модель.

Проводятся несколько экспериментов:

- кросс-валидация с разным количеством фолдов;
- GridSearch;
- RandomizedSearch;
- подбор регуляризации;
- модель с полиномиальными признаками.

### 6. Дерево решений

Проверяется нелинейная модель дерева решений.

Подбираются параметры:

- `max_depth`;
- `min_samples_split`;
- `min_samples_leaf`.

### 7. KNN

Используется метод ближайших соседей.

Так как KNN основан на расстояниях между объектами, перед обучением используется масштабирование признаков.

### 8. Случайный лес

Обучается ансамбль деревьев решений.

Подбираются параметры:

- `max_depth`;
- `min_samples_split`;
- `min_samples_leaf`.

### 9. LightGBM

Используется градиентный бустинг на деревьях.

Для работы с дисбалансом классов используется `scale_pos_weight`.

Сначала параметры подбираются с помощью GridSearch, затем проводится более широкий поиск с использованием Hyperopt.

### 10. HistGradientBoosting

Проверяется реализация градиентного бустинга из `scikit-learn`.

Модель обучается на исходных, немасштабированных данных.

### 11. Нейронная сеть

Используется простая полносвязная нейронная сеть:

- Dense 64;
- Dropout 0.3;
- Dense 32;
- Dropout 0.2;
- выходной слой с sigmoid.

Для борьбы с переобучением используется EarlyStopping.

Для дисбаланса классов применяется `class_weight`.

### 12. CatBoost

Дополнительно проверяется модель градиентного бустинга CatBoost.

### 13. VotingClassifier

Объединяются три модели:

- LightGBM с Hyperopt;
- HistGradientBoosting;
- Logistic Regression.

Весовые коэффициенты перебираются с шагом 0.1, после чего выбирается комбинация с максимальным ROC-AUC на валидационной выборке.

### 14. Стекинг

В качестве базовых моделей используются:

- LightGBM;
- HistGradientBoosting;
- Logistic Regression.

Их предсказания передаются мета-модели Logistic Regression.

### 15. Сравнение моделей

Все модели сравниваются на одной валидационной выборке.

Используемые метрики:

- ROC-AUC;
- Gini;
- F1;
- Precision;
- Recall;
- Accuracy.

Также строятся ROC-кривые.

### 16. Валидация финальной модели

Для финальной модели дополнительно проверяются:

- KS;
- PSI;
- ROC-AUC и Gini на train и validation;
- ROC-кривые;
- корреляция признаков;
- Gini отдельных факторов;
- VIF.

Это позволяет проверить качество модели, устойчивость и наличие признаков переобучения или мультиколлинеарности.

### 17. Финальный Pipeline

Финальная модель объединяется с этапами обработки данных в единый Pipeline.

Pipeline включает:

1. заполнение пропусков;
2. стандартизацию;
3. LightGBM с оптимальными параметрами.

После обучения на объединённых train и validation данных Pipeline используется для получения предсказаний на тестовой выборке.

В проекте сравниваются:

| KNN | метод ближайших соседей |
| Random Forest | ансамбль деревьев |
| LightGBM | градиентный бустинг |
| HistGradientBoosting | градиентный бустинг |

## Финальная модель

В качестве финальной модели используется **LightGBM с байесовской оптимизацией гиперпараметров с помощью Hyperopt**.

Подбор параметров проводится по ROC-AUC с использованием стратифицированной кросс-валидации.

Для учёта дисбаланса классов используется `scale_pos_weight`.
